# 三人团队分工

团队由你、队友 1、队友 2 组成。当前围绕已验证的 W4A8 计算核心，补齐控制、外存传输、软件和层间数据通路；后续推进 FFN 与 Attention/KV。

本文统一三人的职责与近期交付。当前实现状态见 [项目盘点](project_status.md)，上游许可证及适配分析见 [openTPU / llama-fpga 复用报告](upstream_reuse.md)。

## 1. 当前共同目标

打通以下系统仿真闭环：

**软件提交任务 → 内存适配器供数 → 当前 W4A8 核心 → 结果写回 → 完成记录。**

首轮采用单活动任务，覆盖连续两个任务。使用仿真外存验证可综合适配器；实际板级接入在板卡确认后另行安排。

## 2. 三人职责

A–F 是功能范围的简称，不是人员编号：A 控制、B 存储传输、C 计算、D 软件/模型、E 层间转换、F Attention/KV。

| 人员 | 主责 | 上游关注点 | 首个交付 |
|---|---|---|---|
| **你：C + E** | 维护计算核心、片上数据流与数值规格；优化后处理/输出，建立层间转换 | openTPU 量化器、VPU、lib.py / mlp.py；llama-fpga 非线性结构 | 当前 Q16.16 输出→INT8 激活及 group scale 的位精确参考和自检模块 |
| **队友 1：A + D** | 控制 wrapper、任务/张量格式、软件后端、模型导出与系统集成 | openTPU pkg / seq / ctrl、ISA 模拟器、runtime / compiler；llama-fpga 导出与 token 调度 | 软件提交带地址、stride、格式的 W4A8 任务，完成后读取结果；拒绝非法配置 |
| **队友 2：B + F** | 先实现存储请求与 packet 桥接，再推进 KV 管理与 Attention 集成 | openTPU DMA / memory adapter、attention.py；llama-fpga DataMover / KV 布局 | 有限缓冲仿真内存→当前 packet 入口→结果写回，覆盖尾块、暂停和写确认 |

你目前已经完成的主线是 C：INT8/W4A8、4×4/8×8 脉动阵列、权重双缓冲、激活复用、分组累加/缩放与连续波前，并建立了相应验证及工具证据。E 的层间 requant 尚未实现。

队友 2 先交付存储通路，随后承担 KV 与 Attention 集成。Attention 的计算算子由你支持，软件参考和任务依赖由队友 1 支持。

## 3. 三人之间的接口与所有权

| 协作边界 | 约定 |
|---|---|
| 队友 1 → 队友 2 | 锁存任务 ID、M/N/K、A/W/sx/sw/Y 地址、byte stride、格式和 group 配置；非法任务启动前拒绝 |
| 队友 2 → 你 | 沿用当前 tile 请求及输入 valid/ready、data/keep 协议；未接受的数据持稳，尾部不越界 |
| 你 → 队友 2 | 输出坐标、last、signed32 Q16.16 数据及 valid/ready；背压时持稳 |
| 队友 2 → 队友 1 | 全部结果写回并收到写确认后，才允许报告任务成功；out_last 接受不等于写回完成 |
| 三人共同 | 冻结 group/scale、布局、舍入/饱和、复位和错误合同；格式或编译容量不支持时明确拒绝 |

- 计算内核及层间数值模块由你维护；统一顶层、软件任务格式由队友 1 维护；存储桥由队友 2 维护。
- 当前 group size 是硬件配置，任务字段不能自动使其成为运行时可变参数。
- 外层 M/N 切分由队友 1 编译成任务。K 切分须保留未舍入累加状态、最终统一舍入；宽累加工作区未通过验证前拒绝超容量 K。
- 每人负责本模块自检；队友 1 维护系统回归入口，你维护内核/数值回归，队友 2 维护存储协议检查。

## 4. 上游复用口径

- **openTPU：** 主许可证 Apache-2.0，控制、DMA、运行时及量化/非线性机制是复用候选。实际引入时保留固定 commit、源路径、许可证及修改记录；其单独 GPLv3 的 ASIC 工具目录不在本轮复用范围。
- **llama-fpga：** 当前未核实到明确代码授权，先阅读公开架构作参考；取得明确许可后再决定是否引入源码。
- 两个项目都存在数值/接口差异。openTPU 的 FP4/FP32 与当前 INT4/定点格式不能直接互换，DMA 也需要 packet 适配。
- 上游代码尚未接入本工程；复用候选须实际编译、仿真和综合后才标记通过。核查副本保留在 build/upstream_review。

## 5. 推进顺序

1. **单层系统闭环：** 队友 1 做任务提交和控制，队友 2 做供数/写回，你提供稳定计算接口。你的 requant 可独立并行，不阻塞最初单层写回。
2. **两层与 FFN：** 你做 requant、逐元素乘/SiLU；队友 1 做任务图与参考；队友 2 搬运中间张量。
3. **Attention/KV：** 队友 2 做 KV 地址、有效长度、追加/读取及接线；你做动态矩阵乘、归约和 Softmax 等算子；队友 1 做 Prefill/Decode 参考与调度。

每阶段通过后再扩大范围；当前不预设完成日期。

## 6. 共同验收

- 输出逐元素与本项目位精确参考一致，失败和超时返回非零。
- 输入暂停、输出背压、连续任务和复位有自检，尾部访问不越界。
- 写确认完成前不得回报成功，错误不得被旧结果掩盖。
- 记录实际周期、流量、资源和时序；区分仿真、综合/OOC、板上结果。
- 保留当前已验证基线；新增适配和优化版本独立验证后再集成。
