这份说明用于我们三人对齐开发范围、接口和交付。我们以现有已验证的 W4A8 计算核心为基础，先补齐控制、存储传输和软件通路，再推进层间转换、FFN 与 Attention/KV。

我继续负责计算核心与数值模块，两位队友分别负责控制与软件、存储传输与缓存集成。现有实现及验证结果见 [项目盘点](project_status.md)。

## 1. 近期共同目标

先打通以下系统仿真闭环：

**软件提交任务 → 内存适配器供数 → W4A8 核心计算 → 结果写回 → 完成记录。**

首轮采用单活动任务，并验证连续两个任务。外存由仿真模型提供，存储适配器采用可综合实现。实际板级接入在板卡确认后安排。

## 2. 职责与首个交付

| 负责人 | 负责范围 | 首个交付 |
|---|---|---|
| **我：计算与数值（C + E）** | 维护计算核心、片上数据流和数值规格；优化后处理/输出，建立层间转换 | 为系统接入提供稳定的计算接口；并行实现 Q16.16 输出→INT8 激活及 group scale 的位精确参考和自检模块 |
| **队友 1：控制与软件（A + D）** | 控制适配层、任务/张量格式、软件后端、模型导出和系统集成 | 软件提交带地址、stride、格式的 W4A8 任务，完成后读取结果；拒绝非法配置 |
| **队友 2：存储与缓存（B + F）** | 先实现存储请求与输入 packet 桥接，再推进 KV 管理和 Attention 集成 | 有限缓冲仿真内存→当前 packet 入口→结果写回，覆盖尾块、暂停和写确认 |

现有核心已完成 INT8/W4A8、4×4/8×8 脉动阵列、权重双缓冲、激活复用、分组累加/缩放与连续波前，并有对应验证和工具证据。层间 requant 尚待实现。

Attention 阶段由队友 2 负责 KV 与接线，我提供动态矩阵乘、归约和非线性算子，队友 1 提供软件参考和任务调度。

## 3. 接口与代码维护边界

| 协作边界 | 需要对齐的内容 |
|---|---|
| 控制与软件 → 存储 | 任务 ID、M/N/K、A/W/sx/sw/Y 地址、byte stride、格式和 group 配置；非法任务启动前拒绝 |
| 存储 → 计算 | 沿用当前 tile 请求和输入 valid/ready、data/keep 协议；未接受的数据持稳，尾部不越界 |
| 计算 → 存储 | 输出坐标、last、signed32 Q16.16 数据和 valid/ready；背压时持稳 |
| 存储 → 控制与软件 | 全部结果写回并收到写确认后，才报告任务成功；out_last 接受不等于写回完成 |
| 三人共同 | 确认 group/scale、布局、舍入/饱和、复位和错误行为；不支持的格式或尺寸明确拒绝 |

- 我维护计算内核及层间数值模块；队友 1 维护统一顶层、软件任务格式和系统回归入口；队友 2 维护存储桥和协议检查。
- 每位负责人提供本模块自检；共享接口修改先一起确认。
- 当前 group size 是硬件配置，任务字段不能自动使其成为运行时可变参数。
- 外层 M/N 切分由队友 1 编译成任务。K 切分须保留未舍入累加状态、最终统一舍入；宽累加工作区验证通过前拒绝超容量 K。

## 4. 实现过程中可参考的项目

两位在设计和实现时，可以参考以下项目的公开架构与实现，按负责模块选择有用的部分：

| 参考项目 | 适合关注的内容 | 使用边界 |
|---|---|---|
| [openTPU](https://github.com/FeSens/openTPU) | 控制/指令组织、有限缓冲 DMA、软件运行时、量化与向量运算、Attention/KV 的组合方式 | 主许可证 Apache-2.0；代码引入前核对对应文件及第三方许可证，保留来源和修改记录，并完成接口适配与本项目验证 |
| [llama-fpga](https://github.com/adamgallas/llama-fpga) | 完整 Decode 的调度、权重/KV 布局、模型导出、DataMover 接入和非线性模块拆分 | 当前未查到明确代码授权，先用于架构理解；直接引入源码需取得明确许可 |

**这两个项目在本工程中的地位是外部参考和可选模块来源。当前没有上游代码接入本工程，现有构建与验证流程独立运行。**

具体实现以本项目的数值规格、接口和资源目标为依据。参考过程中需要核对格式与行为差异：例如 FP4/FP32 或 AWQ/zero-point 路径不能直接替换当前 signed INT4/定点计算，外存接口也需要适配为当前 tile packet 协议。

许可证、固定版本及具体模块分析见 [上游参考与复用分析](upstream_reuse.md)。是否采用某段代码，由对应负责人完成适配评估后共同确认。

## 5. 推进顺序

1. **单层系统闭环：** 队友 1 做任务提交和控制，队友 2 做供数/写回，我提供计算接口。requant 独立并行，首轮先验证单层写回。
2. **两层与 FFN：** 我做 requant、逐元素乘/SiLU；队友 1 做任务图与参考；队友 2 搬运中间张量。
3. **Attention/KV：** 队友 2 做 KV 地址、有效长度、追加/读取及接线；我做动态矩阵乘、归约和 Softmax 等算子；队友 1 做 Prefill/Decode 参考与调度。

每阶段通过验证后再扩大范围。

## 6. 共同验收要求

- 输出逐元素与本项目位精确参考一致，失败和超时返回非零。
- 输入暂停、输出背压、连续任务和复位有自检，尾部访问不越界。
- 写确认完成前不得回报成功，错误不得被旧结果掩盖。
- 记录实际周期、流量、资源和时序，区分仿真、综合/OOC、板上结果。
- 保留已验证基线；新增适配和优化版本独立验证后再集成。
