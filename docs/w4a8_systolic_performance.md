有效MAC直接累计每PE valid firing，尾块无效槽不计。compute_cycles=接受输入向量的RUN推进拍；array_cycles=RUN+DRAIN推进拍；array_mac_cycles=至少一个有效PE firing的拍数；array_drain_cycles=DRAIN推进拍；array_pause_cycles=RUN/DRAIN被冻结的拍数。compute/post overlap仅RUN有效推进且post活动，排空也可能与post重叠但未纳入此旧指标；load/compute overlap同理。不能用RUN单独作脉动阵列容量分母。全部记录独立闭式审计：固定开销=2RC×输出tile数+2×请求tile数+(RC+2)×group数+2MN+1；总周期=固定开销+array_cycles+array_pause+等输入+等输出+psum满等待+post drain。

理论容量按16/64MAC每推进拍；100MHz仅评估目标，对应1.6/6.4GMAC/s理论值。扩成8×8同时改变PE预算、缓存行数、供数/尾块和RC保存输出开销；必须用同尺寸b4/s4、b8/s8区分拓扑影响。代表性case12为满8×8，case4/13为单行Decode，case14为8×8尾块；case5仅4行，会浪费8×8的行容量。实际资源/时序独立见验证报告，不将理论容量当测得性能。

本轮保守每tile排空对连续供数明确有成本，更多PE也会增加RC逐槽保存/后处理开销。下一步优先比较group内跨tile连续波前，减少D×tile_count为D×group_count，并继续测输出tile流水/psum保存；在做真实优化前保留广播基线。
