# NPU 方向：当前进展与下一阶段

本轮实现了驻留矩阵上的有序描述符 FIFO、任务 ID、完成记录、错误状态与结果确认。已实现边界见 [NPU 架构](npu_architecture.md)，实际验证证据见 [NPU 验证](npu_validation.md)。当前只包含 GEMM/GEMV 一个操作码，尚未连接完整 LLM。

## 按优先级推进

1. **建立独立张量地址与存储视图。** 扩展描述符的 A/B/C 基址、行步长、B 转置视图和容量边界检查。首先使用片上地址空间和独立结果槽，明确读写依赖与结果归属，再允许同批任务使用不同矩阵。验收包括非法跨度、地址算术溢出、重叠区域和 Q×K^T 的逐元素验证。
2. **提高 B 源供数带宽。** 当前 B 源仍每拍一个标量，队列不会消除这个瓶颈。比较按列分银行（每银行真实同步读端口）、打包宽字和 tile 布局变换，保留双缓冲所有权检查。用周期/访存统计决定是否扩阵列；避免只增加 DSP 而不增加带宽。
3. **增加量化后处理和片上算子链。** 明确定义 INT32→INT8 的乘子/移位、舍入和饱和，支持可选 bias；这与累加器回绕规则分别验证。增加中间激活槽和依赖描述符，让两个投影算子间的数据留在片上，逐步覆盖 FFN。当前完成确认由主机读取结果，尚未自动串联后处理。
4. **增加向量与行归约引擎。** 研究 residual、向量加乘、归约；随后独立实现/验证 RMSNorm、SiLU、Softmax、RoPE 的数值方案和误差预算。微指令控制矩阵与向量引擎仍走 NPU 架构路线。
5. **接入真实外部存储和运行时。** 板卡确定后再接 DDR/HBM IP；先实现可变响应延迟的 burst adapter、队列/双缓冲背压和异常恢复。建立主机描述符打包、张量分配和算子图调度，再研究 KV Cache、Prefill/Decode 差异及完整模型。

优先做可独立验收的小增量。Decode GEMV 可以在第 2 项中研究行重映射和 K 归约，但须分别报告读取权重字节数、batch=1 利用率及真实端到端延迟。当前 M=1 功能正确，尚未做 Decode 最优映射。

# 后续研究优先级

## 本轮进展与更新后的优先级

已完成：源 RAM 连续同步读装载、完整 A 行 cache 跨 N 块复用、仅最后 K tile 写回。默认满容量任务从 9872 降为 3540 活动周期；详见 [optimization.md](optimization.md)。未实现 DDR 双缓冲、装载/计算重叠或 B 跨 M 复用。

下一步优先处理 B 装载：当前占 2112/3540=59.66% 活动周期。先比较按列分银行的 B Buffer（明确每银行端口）与 B 双缓冲的周期/资源；建立模拟 burst adapter 和可变延迟供数验证，再接真实 DDR/HBM。完整 A 行 cache 会随 MAX_K 增长，较大层尺寸应回到有界 K tile 和明确的部分和调度，不能无限扩大 cache。

## 第一轮路线记录（以下未完成项仍适用）

以下保留第一轮计划记录；第 1 项的激活复用和最终写回已经在本轮完成，其余未完成项仍为未来计划。当前已经验证的边界见 validation.md。第一版可用于比较地址调度、带宽与周期，不能直接作为完整 Transformer/LLM 推理实现。

## 1. 先降低 tile 装载与 checkpoint 成本

默认 16×16×32 测试的 RUN 仅占 512 个有效周期，serial load 和保存占大部分时间。下一步增加每相位周期计数与每字节搬运统计，把主机装载、片上搬运、有效 MAC、尾块无效 MAC 分开测量。将矩阵 Buffer 银行化，保持严格的每银行端口预算；用 burst 一次填多行或列，复用同一 A tile 与多个 N tile、同一 B tile 与多个 M tile。若不需要调度上下文切换，可以仅在最终 K tile 保存输出，减少中间 checkpoint。若需要切换输出 tile，必须先实现 checkpoint 的同步重读与 PE seed 恢复，并验证交换任务顺序。

验收：所有当前向量仍通过；地址越界断言仍成立；实测周期降低，并能由带宽与状态公式解释。先做资源和周期对比，再决定扩阵列规模。

## 2. DDR/HBM 接口、双缓冲与任务描述符

先确认具体 VU9P 板卡、封装、速度等级、外部内存类型、控制器 IP 和许可。把现在的标量载入阶段替换为有明确 ready/valid 的 burst 适配器；A/B tile 各加两个银行集合，装载下一 K tile 与计算当前 tile 重叠。每个银行集合具有 EMPTY/FILLING/READY/COMPUTING 状态，只有消费者确认完成才可覆盖。以随机内存响应延迟和背压模拟 CDC/FIFO/突发边界，最后接真实内存。AXI、DMA、PCIe 与板级时钟复位分阶段引入，不将片上仿真周期直接换算成板上端到端性能。

验收：双缓冲无覆盖、无未填数据读取；暂停、burst 拆分、错误恢复、非整块尺寸全部自检；先跑小容量 DDR 实机 loopback，再跑 GEMM。

## 3. Decode GEMV 专用调度

当前 M=1 可计算，但只有一行 PE 产生有效输出。研究跨输出列并行的向量点积，或把空闲行映射到不同输出通道/不同 K 分段，再通过明确定义的 INT32 归约合并。采用 weight-stationary 的长期权重驻留，重点比较每 token 权重带宽、片上容量命中率、batch=1 延迟以及多个 token/batch 的利用率。不要仅以 PE 峰值估计 Decode token/s。

验收：所有 GEMV 边界、混合符号与跨 tile 用例逐元素一致；归约顺序遵守回绕规则，量化后处理另行验证；报告端到端实测字节数和延迟。

## 4. FFN 算子链与量化后处理

先实现一层投影 GEMM/GEMV，再加入 INT32→INT8 的 scale、舍入、饱和和可选 bias；这些规则与当前累加回绕是独立的接口合同。扩展到 up/gate/down 投影，规划中间激活 Buffer、融合搬运及权重复用。SiLU、RMSNorm 需要独立数值方案、误差预算和高精度参考，当前未实现。使用固定、可公开复现的小模型张量进行算子验证，然后测量真实模型精度和吞吐。

## 5. Attention 和完整 LLM 调度

先支持明确的 B 转置/步长视图以覆盖 Q×K^T 和概率矩阵×V；增加序列长度、头数、batch 维的描述符与访存追踪。然后规划 KV Cache 的按 token 更新、分页和带宽，分别验证 prefill 与 decode。Softmax、RoPE、KV Cache、RMSNorm、SiLU 均为未来工作；Softmax 的指数/归一化必须单独量化校验，并设计跨 tile 的行归约状态。最后才连接完整 Transformer 调度、模型格式与主机运行时。

## 板级验收

确定板卡后补充真实管脚、I/O 时序、时钟源、复位同步、DDR 约束、功耗和 thermal 检查。执行带板级约束的布局布线与时序签核，再生成 bitstream、上板验证。当前 OOC 内部时序与理论 100 MHz 峰值均不能代替这些检查。
